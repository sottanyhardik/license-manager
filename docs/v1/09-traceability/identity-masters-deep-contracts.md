# Identity, administration and master-data deep contracts

This is a bounded direct-source review of **12 contract groups** covering
identity, privileged user administration, company data, generic masters and
MDS status. It supplements the 142-operation identity/master/sync register;
it does not close its individual-operation denominator. Every group remains
**Partial** because one or more DTO fixtures, direct denial, recovery,
consumer, or approved object/company-policy cases remain absent.

Evidence labels: **C** is verified code, **T** is a named existing test,
**I** is a source-level frontend consumer, **S** is schema/runtime registration
metadata, **P** is a V1 proposal and **D1/D4/D6** require owner approval.

## Cross-cutting evidence and V1 acceptance order

1. D4 must determine refresh/logout/reset-token transport, rotation and revocation requirements before the SPA or endpoints are redesigned.
2. Lock user-management safety: anonymous/wrong-role, self/privileged target and role-assignment tests must precede administrative UX changes.
3. Treat CompanyPermission’s role-scoped multi-company visibility as verified current behavior, not a security defect or a tenancy policy. D1 must supply any desired object/company restrictions.
4. For every dynamically generated master family, freeze serializer-specific positive, validation, protected-delete and MDS-down fixtures before replacing common CRUD/UI infrastructure.
5. MDS status is a truthful operational read model, not proof that peer-sync/beat/deployed MDS health is correct; validate those separately.
