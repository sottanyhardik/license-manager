# Task and activity/audit function contracts

**Bounded source audit — 12 contracts.** This document separates three
different concepts that must not be merged in V1 merely because each is called
an “audit” or “task” in a UI:

1. `apps.tasks` is an authenticated personal work-item workflow.
2. `ActivityLog` is a best-effort, asynchronous API-activity stream.
3. `ReconciliationLog` is a reconciliation-specific append-only record written
   in the same atomic transaction as selected financial mutations.

`C` means direct source inspection and `T` names an existing test. Every row
is **Partial**. Static imports and a route registration are not evidence that
all callers, authorization branches, delivery guarantees or browser behavior
have been exercised. D6 is the owner decision governing whether any stream
must meet compliance-grade durability.

## V1 guardrail

`ActivityLog` cannot be cited as proof that a financially consequential action
was durably recorded: it is post-response, asynchronous, daemon-backed,
exception-swallowing and disabled in test execution. `ReconciliationLog` has
a materially stronger intended contract for its bounded domain, but it does
not make the entire application's activity history durable or immutable.

The next audit/implementation tranche must attach individual task/API IDs,
browser consumers and endpoint tests to TAF-06–08, then obtain D6 before
making compliance, retention or non-repudiation claims.
