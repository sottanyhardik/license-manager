# Ledger and report function contracts

This bounded review covers **15 high-consequence ledger/report/export
functions and view boundaries**. It distinguishes a canonical ledger DTO from
the older licence balance/reconciliation breakdown: they have different
purposes and neither may silently replace the other. `C` is direct current-code
evidence; `T` is a named current test with narrow evidence; `S` is static
dependent/import evidence, not a proven call. Every contract remains
**Partial**. D2 governs financial/customs meaning and D5 governs accounting
claims.

## Current source-of-truth boundaries

- **C:** `CanonicalLedgerService` owns a financial trade collection: PURCHASE
  credits, SALE debits, COMMISSION visible but excluded from balance, and an
  opening state. Its `company_id` parameter filters ledger data but does not
  authorize the caller ([canonical service:84](../../../backend/apps/license/services/canonical_ledger_service.py#L84)).
- **C:** `LicenseBalanceLedgerBuilder` owns the one-licence financial/customs
  breakdown and reconciliation relationships. Its header states it consumes
  the same annotated rows as the balance calculator, rather than becoming an
  independent balance engine ([builder:1](../../../backend/apps/license/services/license_balance_ledger_builder.py#L1)).
- **C:** Excel/PDF renderers take already materialized canonical dictionaries;
  they deliberately do not import a model or business service
  ([Excel renderer:1](../../../backend/apps/license/services/exporters/financial_ledger_excel_renderer.py#L1),
  [PDF renderer:1](../../../backend/apps/license/services/exporters/financial_ledger_pdf_renderer.py#L1)).

## V1 guardrails and test order

1. Retain canonical financial ledger, customs balance breakdown and
   reconciliation tracks as distinct labelled representations until D2 and
   D5-approved golden data proves a change safe.
2. Any caller supplying `authorization_company_id`, `company_id`,
   `license_ref`, or document-link user context must have a D1-approved
   role/object/company test; data filtering is not authorization proof.
3. Contract-test public exports for invalid filter, empty collection, JSON/
   PDF/XLSX parity, wrong role, file-generation failure and protected-link
   expiration. Add query/memory budgets for list and large detail exports.
4. Renderers must remain presentation-only. A proposed renderer refactor may
   not query models, calculate balances or derive a new SION/financial total.

This adds 15 bounded contracts only. It does not change the 354-operation,
57-route, or 8,046-symbol completion denominators.
