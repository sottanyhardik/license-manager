IMPORTANT CORRECTION to the claim's "Live evidence of the blast radius"
narrative: for the two flagship examples the finding leads with (port 513,
company 138), calling DELETE today would NOT silently cascade-delete 171
licenses / 436 BOEs / 37 allotments (or 48 BOEs / 21 allotments) in one
transaction as the notes.md prose states ("would cascade through Django and
permanently remove all 171 licenses ... in one transaction"). It would
instead raise a clean ProtectedError and roll back with ZERO rows deleted,
because unrelated on_delete=PROTECT relations further down the same CASCADE
graph (InvoiceBOEAllocation, IncentiveTradeLine, LicenseTradeLine,
LicenseOwnership.current_owner) currently happen to block it. The
investigate-stage notes.md does explicitly caveat this possibility in one
sentence ("unless a downstream PROTECT relationship ... happens to block
part of the chain -- which is incidental, not a deliberate safeguard") but
the "Live evidence" section itself asserts the full 171/436/37 wipe as if it
would actually execute, which this independent check falsifies for that
specific example.
