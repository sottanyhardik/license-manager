# P0/P1 regression-test contracts

This is a bounded test-to-requirement trace, not a substitute for the 509-test-symbol denominator or a claim of endpoint coverage. It identifies **16 consequential current tests** and states the narrow behaviour each proves. A test file's existence, a passing historical suite, or a broad feature test does not close an API/route contract.

Evidence labels: **T** = verified by direct inspection of the current test; **C** = related code/API evidence in existing V1 registers; **P** = V1 acceptance test proposed; **D** = owner decision. Every end-to-end contract remains **Partial** because the relevant role/object/browser/recovery matrix is not fully demonstrated.

## Evidence limits and next test tranche

The tests above establish **narrow current behaviour only**. They do not prove all callers, serializers, errors, roles, company scope, storage semantics, browser interactions, migration compatibility or production configuration. Their direct parent records are [P0/P1 API deep contracts](p0-api-deep-contracts.md), [security-critical paths](security-critical-paths.md), [critical workflow test map](critical-workflow-test-map.md), and [the route/API acceptance register](p0-p1-route-api-contract-register.md).

The next executable tranche should add named tests in this order:

1. P0 direct-API anonymous, wrong-role, partial-dual-role and D1-approved object/company cases for allocation, hide/restore, reconciliation link/merge/note and protected media.
2. Race/retry/rollback tests for allocation capacity, merge, replan dispatch and ledger package/download jobs.
3. D2/D3-approved golden dataset tests that assert the exact labelled Customs and Financial outputs across reports and exports.
4. Repaired browser tests for loading, empty, success, error and denied states on the listed P0/P1 routes; the current E2E baseline cannot act as a green gate.

## Measurement

This register maps 16 selected requirements to direct current test functions. It raises no global numerator: the test-symbol mapping population, complete API contracts and complete frontend contracts remain `0` in [traceability coverage](traceability-coverage.md) until the prescribed per-unit closure evidence is recorded.
