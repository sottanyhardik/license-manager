# Master rebuild roadmap

| Milestone | Objective | Exit approval |
|---|---|---|
| M0 | Access, source-index, repository/deployment baseline | Architecture/audit lead |
| M1 | File/route/API/job/model inventory and test baseline | Audit lead + owner |
| M2 | Workflow, rule, permission and database/migration mapping | Owner/domain/CA as applicable |
| M3 | Target architecture, compatibility and migration design | Architecture board / owner |
| M4 | New foundation: CI, tenancy, auth, audit, test data | Security + QA |
| M5 | Licence ledger and DFIA/SION/AU/restriction engine | Domain owner + QA |
| M6 | BOE/trade/documents/reconciliation/report read models | Operations owner + QA |
| M7 | React routes/work queues/export parity | Operations UAT |
| M8 | Accounting, parallel close and CA acceptance | CA + owner |
| M9 | Migration dry runs, regression/security/performance/recovery | Release board |
| M10 | Staging acceptance, cutover and hypercare | Explicit production approval |

Detailed task dependencies are in `developer-tasks.csv` and `dependencies.mmd`. Milestones are gates, not calendar promises.
