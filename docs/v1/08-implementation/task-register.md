## Sequencing rules

1. T00 always applies. T01–T02 cannot be bypassed by encoding a policy guess into code, a query or a UI condition.
2. T03–T04 produce evidence rather than behavior changes and can run in parallel by domain.
3. T05–T09 protect financial, access and data integrity before UI replacement. Preserve compatible representations until reconciliation/rollback evidence is accepted.
4. T10–T12 must name their API/route/migration/authorization dependencies. Frontend gates never substitute for direct API authorization.
5. T13–T15 are release gates. The current E2E result is failing and cannot support readiness.

## Completion evidence

Each completed task appends identifiers, actual commands/results, migration/data impact, rollback or forward-recovery procedure, owner approval where applicable, and changed risk/traceability numerator. The [contract-closure protocol](../09-traceability/contract-closure-protocol.md) defines promotion from Partial to Verified.
