# Individual API contract register — identity, masters, sync and operations

This register adds bounded individual-operation contract evidence to the generated [API operation register](api-operation-register.tsv). Its rows name every operation in scope; a shared row is used only where the registered router action and implementation are the same. All rows remain **Partial**: OpenAPI registration plus source inspection is not proof of every consumer, object-scope policy, response fixture, or failure test.

Evidence labels: **C** = verified by code; **S** = generated schema/register; **T** = named existing test discovered or executed in the V1 baseline; **I** = inferred client consumer. The companion [P0/P1 route/API contract register](p0-p1-route-api-contract-register.md) owns browser-state gates.

## Bounded coverage and closure rule

This document gives direct contract fields to **142 registered operations**: API-018–034 (17), API-163–171 (9), API-172–248 plus API-254–267 (91), API-249–253 (5), API-268–269 (2), API-315–320 (6), and API-321–332 (12). It does not mark any operation complete because per-operation consumer, DTO fixture, negative role/object policy and recovery test evidence remains incomplete. The count is an individual-operation source-contract mapping denominator, not a successful acceptance count.

An operation changes from `Partial` only after a linked test proves its request/response fixture, anonymous/wrong-role (and D1 object/company) result, data/task side effect and declared recovery behavior.
