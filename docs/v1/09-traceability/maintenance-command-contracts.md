# High-risk maintenance command contracts

**Bounded source audit — 12 of 73 discovered management-command modules.**
Commands are operator entry points, not authenticated DRF operations: their
effective authority is the shell/deployment identity and database/storage
credentials. This record does not prove a production runbook, scheduler,
backup, database state or operator authorization. Every row is **Partial**.

`C` means the stated behavior was read in the current command source; `T`
means a named repository test is present. A dry-run flag is not treated as a
backup, approval or recovery plan.

## Cross-command control requirements

1. Invoke write commands only through a named deployment/operator role; no
   Django/DRF permission class controls them.
2. Record exact command, flags, code commit, target environment, operator,
   input/report artefact checksums, start/finish and row/value reconciliation.
3. A dry run must be reviewed before any write run. A pre-run backup and a
   forward-recovery plan are mandatory for migration/schema/balance commands;
   test restore, not just backup creation.
4. Do not equate command idempotency with safe interruption: a per-row or
   per-batch commit can require reconciliation after a process/database loss.
