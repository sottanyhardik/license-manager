# Peer sync and background execution contracts

This is a bounded direct-source audit of **12 asynchronous and peer-sync
contracts**. It supplements the 11 signal/task modules and 73 management
command modules already inventoried; it neither proves production scheduler
registration nor converts the global backend-symbol denominator to complete.

Evidence labels: **C** = verified in current source; **T** = named current
test evidence; **I** = static registration/import evidence only; **P** = V1
proposal. Every row is **Partial** because a local test or code path does not
prove production broker, peer, scheduler, storage or restore behavior.

## Registration and operations limits

`CoreConfig.ready()` is only static evidence that outbox/cache signal imports
are attempted. The application can still have deployment-specific settings,
worker process imports, Celery beat schedules, peer credentials, reverse
proxies, network/TLS, broker durability and storage behavior not represented
by that source. The current 25-test isolated MDS baseline and core/licence
test baseline are helpful but do not execute those external-state conditions.

## Required next acceptance tranche

1. In an isolated production-like environment, prove peer credential rotation,
   push/pull replay after a network partition, cursor restore, conflict
   handling and outbox/inbox recovery from backup.
2. Run controlled broker publication failure, worker termination and duplicate
   delivery scenarios for sync media and licence replan; retain data and event
   audit evidence.
3. Record authoritative Celery beat/worker deployment configuration and alert
   ownership; then map every sync/replan signal registration to actual process
   startup. Do not derive an operating schedule solely from task decorators.

This adds 12 bounded contracts only. It does not mark the 11 signal/task
modules, 73 maintenance commands, 354 API operations or 8,046 static backend
symbols complete.
