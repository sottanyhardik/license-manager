# Frontend maintainability contracts

**Bounded static-source audit — 15 shared frontend contracts.** This register
identifies ownership and safe modernization boundaries; it does not establish
browser behavior, direct API authorization, or a requirement to refactor
working code. `C` is source evidence, `T` is a named current test, `S` is
static dependent evidence, and `P` is a V1 proposal. Every row is **Partial**.

## Implementation guardrails

1. Shared client, auth, route, navigation, table and form changes need the
   indexed-consumer audit before an edit, not merely a local component test.
2. A UI role guard, hidden button, optimistic update or client calculation
   cannot close backend authorization, balance or object-scope requirements.
3. Prefer feature adapters and contract tests around the existing seams over a
   framework rewrite. The current architecture supports staged migration.
4. Each extraction must preserve request paths/payloads, redirects, keyboard
   handling, error recovery and existing test assertions, and then add the
   missing API/browser acceptance evidence from the route closure queue.
