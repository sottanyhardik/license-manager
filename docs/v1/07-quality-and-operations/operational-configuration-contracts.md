## Safe operating sequence proposed for V1

1. Use the [live schema/recovery evidence protocol](../06-data-and-migrations/live-schema-and-recovery-evidence-protocol.md) on an approved isolated environment; do not run `db-tools.sh` restore/sync against unknown data.
2. Record branch/commit, migration graph, artifact and configuration-diff identities; verify backup availability before any data-affecting rollout.
3. Validate nginx syntax and service unit semantics on a disposable or staged host before a controlled reload/restart. Verify HTTPS, protected media, API, static, worker and beat readiness separately.
4. Exercise rollback as a forward-recovery decision: stop rollout, restore only from an approved backup in the agreed environment, and retain migration/data audit evidence. Do not promise a blind reverse migration.

## Deliberate exclusions

Ignored environment/credential files, remote host contents, live DNS/TLS,
database data, backup archives, logs and production process state were not
read. This document proposes verification; it reports no deployment result.
